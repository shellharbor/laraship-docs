# Argument coverage

Audited on 2026-10-23 against LaraShip 1.3.0, source [4dfec97](https://github.com/shellharbor/laraship/tree/4dfec97ae4c227fe35cf84f5ac5b5e65b18a1c30). Current upstream main, [285641c](https://github.com/shellharbor/laraship/commit/285641c460f85519a76f97dbdcf9a76ade5fb2dd), differs only in README/CHANGELOG; runtime contracts remain pinned. The supplied context was checked as reference material against the actual parsers.

The public **Arguments** section (`#arguments`) searches 102 entries across deployment, lifecycle, Python adapter and Kubernetes namespaces. Every entry includes accepted values, defaults, a deployment config key where supported, an immutable source link and a link to controls. The generated [deployment flag table](cli-options.md) and typed [full catalog](../src/data/argumentCatalog.ts) are maintained separately because these commands accept different arguments.

| Capability | Website location and behavior |
| --- | --- |
| New Laravel version | Basic offers 13.0/12.0. Advanced accepts an upstream-compatible X.Y constraint, minimum 12.0. This is syntax validation, not a claim that every entered release exists. Existing applications retain their dependencies. |
| Existing repository | HTTPS, SSH and SCP by default; Advanced opt-in adds HTTP, git:// and local file://. Embedded credentials/query/fragment/control characters are rejected. Docker mounts local repositories read-only at the same absolute path. |
| Slug, domain, database, identities, modules, presets, ports, SSL | Existing six-step configurator, dependency validation and compatible multi-preset selection. CLI aliases are documented as equivalent behavior rather than duplicate switches. |
| Custom passwords | Fine-tuning → Custom passwords provides server-only templates for PostgreSQL, MySQL app/container-root, Redis, Filament and Basic Auth. Only applicable flags are emitted. Native MySQL still requires its separate existing host root password. No actual password is accepted by the site. |
| Templates and config | Output/config visibly retain placeholders; optional hidden-input Bash helper substitutes variables on the server. Process-argument visibility remains disclosed. Config stays data, never shell-source. |
| Legacy endpoint and final completion | Separate PUT and POST/script controls with separate target trust; default HTTPS. Explicit allow-insecure-endpoint opt-in and acknowledgement enable HTTP for both endpoint features. Scripts, token paths, timeout and optional report secrets retain their existing behavior. |
| Toolkit and configuration paths | Installation → Execution paths controls native directory and server config path across installation, deployment, inspection and management output. |
| CLI image and archives | Same disclosure accepts exact release-tag/digest overrides after trust acknowledgement; default remains audited immutable image. Docker archive option/env/bind and native LARASHIP_ARCHIVE_DIR are distinct. Directories must already exist. |
| Read-only inputs | Repeatable Python --mount-readonly or direct Docker mounts; key, local repo, config, completion script/token are added automatically. Reject mounts hiding toolkit/system/server/archive paths and Python CSV-incompatible paths. |
| Inspection | Operations → Inspect toolkit generates help, version, list-modules and list-presets through all four runners. No operation executes in the browser. |
| Inventory and updates | Operations → Project management: list and update, including --slug, --no-migrate, --reset, --force and stored/replacement/explicit-empty --post-deploy. Reset and replacement code require appropriate intent. |
| Database dumps | now/list/restore, basename selection and restore-only --yes. Requires an existing backup-enabled project; database dumps differ from ZIP archives. |
| Activation and removal | activate/deactivate accept only --slug. remove uses --slug/--domain and optional native MySQL root template, retains terminal yes and never invents --yes. These operations have no dry-run. |
| Kubernetes | Separate render/deploy generator with all name/namespace/configmap/secret/revision/image/context/replicas/worker/pull-secret/readiness arguments. Requires existing immutable app configuration and a built Laravel application image. Render is offline; deploy requires target acknowledgement and Docker kubeconfig. No server socket, privileged mode or Compose deployment mounts. Python adapter does not support this namespace. |
| One-off Compose tool | Results disclosure emits an administrative tools-profile service and config/pull/run commands. Finite process, no restart, host/server mounts, read-only inputs and a bounded completion grace period. It is not the application workload. |
| Environment and versions | Arguments notes explain versions.env, LARASHIP_ARCHIVE_DIR, KUBECONFIG, precedence and unsupported remote-daemon/internal-marker overrides. PHP image version changes remain a manual template operation rather than an invented CLI flag. |

Execution settings, lifecycle/Kubernetes forms, extra transports, custom-secret selections and HTTP trust are memory-only and reset on Clear data/reload. Saved safe stack preferences retain their existing allowlist. The technical argument descriptions retain upstream English in both UI languages; controls and surrounding guidance support English/Russian.

Verification boundaries: browser checks syntax and compatibility, not server files, ownership, release availability, DNS, credentials, native DB connectivity or cluster access. Tests exercise audited dry-runs, extracted lifecycle parsers, offline Kubernetes rendering and Compose validation; they never execute a deployment, update, restore, removal, hook delivery or cluster rollout. See [verification report](testing.md).
